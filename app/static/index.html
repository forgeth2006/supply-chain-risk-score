1. Name similarity (Signal 1)

Is this name suspiciously close to a popular package?

Try: reqeustsreuestsdjanggonumpyyflask-restpluskubernetes

The real Spark job

Runs our actual Spark ML pipeline in a separate process: NGram(2) → CountVectorizer(binary) → MinHashLSH → approxSimilarityJoin. Left side = your name + the 75 PyPI shortlist candidates; right side = the 15,000 popular names. Needs Java + pip install pyspark; first start takes 10-40 s.

What to say: "A name is cut into overlapping 2-letter pieces. Two names are close when they share many pieces (Jaccard). Comparing against every popular name is fine for one name, but not for 884,779 x 15,000 names. MinHash gives each name a short fingerprint and LSH only compares names whose fingerprints collide. The slider shows the trade-off: more tables find more true matches but compare more names."

3. Blast radius (Signal 2)

If a lookalike of this popular package were malicious, how many other packages could it hurt?

Try: requestsflaskexpresselectronwheel

Why this is a live API call and not our Neo4j graph

Our Neo4j graph stores forward edges only (what a package depends on). Blast radius needs the reverse (who depends on it), so we fetch the count from ecosyste.ms (deps.dev as backup). In scoring: s2 = log(1+dependents) / log(1+largest). A missing value means unknown, never zero.

What to say: "An attack on a package nobody uses is a small problem; an attack on a package thousands of projects depend on is a big one. This page asks a public index live and turns the count into a 0-1 number."

4. Real-world evidence (Signal 3)

Is anyone actually using this lookalike name?

A. GitHub Code Search (live)

Needs a GitHub token in the box at the bottom-left (GitHub requires one for code search). Without it you still see the saved result from our earlier run. Try: wheeel4electron3routeranima

B. GH Archive scan (live, one hour)

GH Archive records every public GitHub event. This downloads one hourly file (tens of MB), reads every event and counts pushes to repos named like our 150 candidate names. The project's full run did the same over 168 hourly files (12,061,354 events) with Spark.

What to say: "A lookalike nobody uses is not dangerous yet; one that shows up in real requirements files is. Hit counts above 5,000 are ignored because those are common English words. A hit shows the name exists in files, not that someone was attacked."

D. Re-run the whole validation script

Runs scoring/validate_openssf.py: clones the OpenSSF list (names only), recomputes overlap and recall, rewrites the data files. Needs git and internet; takes under a minute.

Result, stated honestly: 6 of 70 npm candidates and 0 of 74 PyPI candidates are on the list. Combined-score AUC is about 0.47 (about 0.35 within npm), i.e. no better than chance. Signal 2's apparent 0.74 comes from npm packages having far more dependents than PyPI, a confound, not skill. We did not retune weights on 6 positives (overfitting).
What to say: "We tested our own score against real attacks and report the negative result. The score measures how much damage a lookalike could do if it were malicious; it does not by itself detect malice. Malicious packages are removed quickly, so they have little GitHub footprint."
